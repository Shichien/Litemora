# ReplayMod 原始录像播放

空间管理页的文件选择器同时接受 `.litematic`、`.schem` 和 ReplayMod 原始 `.mcpr`。选择录像后会在浏览器中解析、预览；点击「保存录像作品」会保存原始文件和缩略图，作品列表及原有作品网址会自动打开录像播放器。

## 使用

1. 在 Minecraft Java 版中用 ReplayMod 录制并正常结束录制，取得 `.mcpr` 文件。无需导出视频，也不需要另做 Litematica 文件。
2. 打开空间的管理页，使用导入文件入口选择该文件。
3. 等待解析和资源加载，检查预览。可播放 / 暂停、前后移动 50 ms、拖动时间线、选择 0.25–4 倍速度及循环播放。
4. 拖动画面旋转、右键平移、滚轮缩放；点击画布后用 WASD 移动、Q / E 升降，Shift 加速。「回到录制位置」回到当前时间的录制者位置。
5. 填写作品名称、选择公开或私有，再保存。保存后可从作品列表进入，刷新网址仍能播放。

公开录像会包含录制中收到的整个周边场景。私有录像沿用空间作品的鉴权和源文件访问规则。浏览器不会请求录像中附带的资源包下载地址，也不会执行录制服务器的插件消息。

| Minecraft Java 版 | 协议 | 验证范围 |
| --- | --- | --- |
| 1.20 / 1.20.1 | 763 | 独立二进制测试、真实 ReplayMod 录像、浏览器导入与保存回放 |
| 1.20.3 / 1.20.4 | 765 | 独立二进制测试、真实 ReplayMod 录像、浏览器导入播放 |
| 1.21 / 1.21.1 | 767 | 独立二进制测试与播放状态集成测试 |
| 1.21.4 | 769 | 独立二进制测试与播放状态集成测试；矿车移动包按原版 54 字节步长修正 |

其他版本会明确拒绝，包括当前未接入的 1.21.2 / 1.21.3、1.21.5 及后续版本、26.x。该版本范围与红石 WASM 模拟器的 Java 26.1.2 规则不同。不要改写录像里的版本号来绕过检查。

支持 ReplayMod 格式 14 的 LOGIN / CONFIGURATION / PLAY 状态转换，以及这些协议允许的旧格式直接 PLAY 入口。模组自定义方块、实体、协议或注册表不能视为受支持的原版录像。

## 重现范围

- 读取 ZIP 中的元数据与 `recording.tmcpr`，在 Worker 中解析原始时间戳和协议包。
- 保留区块快照、区块卸载、单块与多块更新、维度切换、方块实体数据，以及实体生成、移动、元数据和移除。
- 按录制顺序应用同一时间戳的事件。倒退时从原始事件重建状态，不倒放物理，也不改写录制中的区块数组。
- 使用 Minecraft 资源模型显示方块、可用的实体模型、掉落物和下落方块。草的旧名称 `grass` 会在资源包只提供 `short_grass` 时作显示层映射，录制状态不变。
- 仅绘制相机目标附近约 48 格的场景；移动相机时继续从已解析状态构建周边。播放会在场景重建时等待，因此复杂场景的实际播放速度可能低于设定倍速。
- 普通活塞的六方向直线推送、最多 12 个已知可推动实心方块、粘性活塞单块拉回、普通收回和 action 2 不拉回，可根据录制的 block action 补齐即时终态。复杂粘液 / 蜂蜜粘连、移动中活塞、未知反应、方块实体等情况会提示不支持，不能保证这种机器的完整画面。

这是一套原始录像的网页播放器，尚未实现完整 Minecraft 客户端。声音、粒子、原始光照、生物群系配色、玩家自定义皮肤、装备、骨骼动画、特殊实体姿态、复杂方块实体外观和 ReplayMod 相机关键帧暂不还原；实体位置随记录的数据包更新，活塞没有平滑移动插值。缺少资源的模型会以线框表示并提示。

树生长、流体变化和生物移动若在录像中有对应的方块 / 实体更新，可以展示；播放器不会重新运行随机刻、流体或 AI。两份真实验证录像是公开问题附件中的场景录像，含流体、植被、方块变化、实体移动和下落方块，不能据此宣称已验证所有树场、刷铁机或刷石机。

## 大小与资源限制

- 空间持久化保留现有 **15 MiB 原文件上限**；大于此值可以本地预览，但不能保存到空间。
- 本地 ZIP 上限 128 MiB；解压后的录制流上限 256 MiB；压缩包声明的总展开大小上限 384 MiB；最多 256 个 ZIP 条目。
- 单包上限 8 MiB、最多 200 万包和 50 万事件、解码分配估算上限 192 MiB、最多 10 万活动实体、维度高度上限 1024、时间范围上限 7 天。高度压缩或更新特别密集的短录像也可能触及限制。
- 这些是解析预算，不是浏览器总内存承诺；模型、纹理、GPU 缓冲和 Worker 传输还会占用内存。建议上传只覆盖目标机器、时长较短的录像。
- 损坏 ZIP、CRC / 帧长度异常、版本不匹配、非法状态编号、未知协议包或超限会显示错误，不作为成功导入保存。

## 实现与验证

- 解析、Worker 与时间线：`src/js/replaymod/`。协议表来源与针对已知上游错误的修正在该目录的数据说明中记录。
- 上传、播放器与作品页面：`src/vue/components/replaymod/`；管理页保留原有 Litematica 导入分支。
- 作品 `kind` 由实际文件扩展名派生，录像的 `replay` 摘要只保存受约束的版本、协议与时长。服务端仍按原始字节数限制文件大小，源文件权限沿用现有接口。
- 本轮真实样本来自 [ReplayMod issue #927](https://github.com/ReplayMod/ReplayMod/issues/927) 的 [原始附件](https://github.com/ReplayMod/ReplayMod/files/13811595/replay_recordings.zip)。附件未发现明确再分发许可，只在本地 `output/replaymod-validation/` 下载使用，不放入产品资源。
- 可复现的浏览器验证和原文件 SHA-256、原始包计数在本地 `output/replaymod-validation/`。测试使用生产构建、Edge、临时本地端口和隔离的 mock 存储，不写入用户现有作品库。

```powershell
node --test tests/
node node_modules/vite/bin/vite.js build
node output/replaymod-validation/browser-check.mjs
```

浏览器验证覆盖真实录像预览、实际非空画面、播放 / 暂停、前后跳转、保存后原网址刷新、源文件字节一致性、损坏文件拒绝、连续替换文件使用新画布、等待保存检查时换文件不会误上传新文件，以及从录像切回 Litematica 后原有预览仍能渲染。真实样本需要按上述来源另行下载。
